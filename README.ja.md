<h1 align="center">Auday Skill</h1>

<p align="center">Auday が知っていることを、あなたのワークフローへ</p>

<p align="center">
  <a href="README.md">English</a> &nbsp;·&nbsp; <a href="README.zh-CN.md">简体中文</a> &nbsp;·&nbsp; <strong>日本語</strong>
</p>

**Auday のデータは、iPhone と Mac の間でローカルの暗号化プロトコルを使って直接転送され、クラウドサーバーを経由しません。**

いつものデスクトップ AI アシスタントで会話を探し、記憶どうしを結びつけ、プロジェクトの概要をまとめる。Mac の計算資源を使って録音を詳しく分析することもできます。iPhone のデータへのアクセスは常に読み取り専用で、利用する情報には出典が保持されます。

## デスクトップ Agent からインストールする

ローカルの Skill に対応したデスクトップ Agent を開き、次のように依頼してください。

> https://github.com/666ghj/auday-skill から、このアプリで使えるように Auday Skill をインストールしてください。初回設定を行い、ローカル意味検索の導入を提案してから、iPhone の Auday への接続を案内してください。文字起こし用のツールは必要になったときに準備してください。

Skill の保存先やインポート方法はアプリによって異なります。利用中のアプリが対応する場所にインストールし、Skill が認識されることを Agent に確認してもらってください。

Agent が利用中のアプリの Skill インストーラーを使い、新しい Mac の環境を確認して、必要なツールを準備します。Python や Homebrew をあらかじめ自分で入れたり、ターミナルでコマンドを順番に実行したりする必要はありません。macOS がシステムパスワードやライセンスへの同意を求める場合は、Agent がその手順を説明し、完了後に続行します。

初回は**ローカル意味検索**の導入を提案します。モデルは 333.59 MB、実行環境のアーカイブは約 11.2 MB です。基本環境の準備が必要な場合は、さらに約 40 MB をダウンロードします。展開後のファイルとインデックスには追加の空き容量が必要です。今すぐ導入するか、後にするかを選べ、その選択は保存されます。導入しなくてもキーワード検索は使えます。モデルの利用には [Gemma 利用規約](https://ai.google.dev/gemma/terms)が適用されます。

**文字起こしは必要になったときに準備します。** 依頼に応じて Agent が適したモデルを一つ選び、ダウンロード、ハッシュの確認、設定、動作検証を行います。匿名の話者ラベルは既定で有効です。「話者を区別しないで」と伝えると、話者モデルと関連パッケージの導入を省きます。

ダウンロードや準備では、現在の段階と実測の進捗を表示します。ツールの準備完了、iPhone の接続、初回同期の完了は、それぞれ区別して案内します。詳しくは[初回設定ガイド](references/first-run.md)をご覧ください。

アプリに専用インストーラーがない場合は、対応する Skill フォルダーにパッケージをコピーできます。Python がすでにある環境では、同梱のローカルインストーラーも利用できます。

```sh
python3 tools/install.py --destination ~/.agents/skills/auday
```

利用中のアプリが対応する保存先を指定してください。このインストーラーがコピーするのは Skill の実行コード、参照資料、メタデータ、ライセンス、バージョン情報のみで、モデルは準備しません。既存のインストールを上書きせず、ホストアプリの設定も変更しません。新しい Skill が認識されない場合は、ホストアプリを更新または再起動してください。その後、Agent がインストール先の `scripts/bootstrap.sh` を実行して初回設定を完了します。この手順には、既存の Python は不要です。

## iPhone に接続する

接続前に、iPhone と Mac を同じ Wi-Fi に接続してください。確認画面が出たら**ローカルネットワーク**へのアクセスを許可し、転送中は iPhone の接続ページを開いたままにしてください。

1. iPhone で「設定 → Connect to your workflow」を開きます。
2. 「すべてのテキスト」または「テキストと音声」を選び、接続を有効にします。どちらも読み取り専用です。
3. デスクトップ Agent に Auday への接続を依頼します。iPhone が生成した通信用パスワードはローカルの入力画面に入力し、チャットには送信しないでください。
4. 同期中は iPhone の接続ページを開いたままにし、取得した情報を Agent に活用してもらいます。

依頼の例：

- 「リリースについて、最終的に何を決めた？ 元の会話も示して。」
- 「今週のプロジェクトの会話から、引き継ぎ用の概要をまとめて。」
- 「今日の記憶を振り返り、明確に約束したことと、今後の対応候補を分けて。」
- 「この録音を Mac で分析して。元の時間軸との対応関係は保持して。」

Agent はキーワード検索に加え、概念や言い換えを探す[ローカル意味検索](references/semantic-search.md)を利用できます。初回設定で意味検索を選んだ場合は、最初の同期後に永続インデックスを作成します。外部の埋め込み API にテキストを送信しません。同期、索引作成、音声分析では、処理段階と実際の処理件数を表示します。

同期した資料はディスク上の SQLite データベースに保存され、Mac を再起動しても残ります。[読みやすいファイルへの書き出し](references/context.md#readable-files)を依頼すると、目次と日付ごとの Markdown が作成され、テキストエディターで閲覧や全文検索ができます。

## 動作要件

- 基本クライアントは macOS 13 以降、指定の意味検索実行環境は macOS 13.3 以降に対応します。
- 「Connect to your workflow」に対応した Auday の iPhone 版。iPhone と Mac は同じ Wi-Fi に接続してください。
- iPhone への接続と組み込み音声ツールのビルドには、Swift 5.9 以降を含む Xcode Command Line Tools が必要です。Agent が有無を確認し、必要なら Apple のインストーラーを起動します。本人による操作が必要なシステム画面は、この Mac 上で処理します。
- 必要に応じて、Agent が専用の `uv` と管理対象の Python を準備します。既存のグローバル Python や Homebrew は前提にしません。
- モデルはパッケージに同梱していません。選んだ機能の設定時に Agent がダウンロードし、ハッシュとローカルでの動作を確認します。

基本的な接続とコンテキストの取得に、AI API キー、Auday のクラウドアカウント、クラウド中継サーバーは必要ありません。

録音を詳しく分析する場合は、[言語別の選定ガイド](references/audio-language-routing.md)に沿って、日本語、中国語と方言、英語、韓国語、フランス語、ドイツ語、複数言語が混在する会話などに適した方法を Agent が選べます。[Mac 向け音声ガイド](references/mac-audio-models.md)では、話者分析と計算資源の使い方も説明しています。録音に合わせてツールを調整し、すでに良好な結果が得られている構成はそのまま活用できます。

組み込みの文字起こし設定では、Mac と用途に合わせて多言語 Whisper `small` Q5_1（190.09 MB）または large-v3-`turbo` Q5_0（574.04 MB）を選び、既定では約 30 MB の話者モデルも準備します。実行プログラムと依存パッケージのダウンロードは別途必要です。Agent は選択した一つの構成を導入し、以後は再利用します。ガイドにある他のエンジンには個別の設定が必要です。匿名の話者ラベルは実在する人物の身元を特定するものではありません。

## データとプライバシー

ネイティブの接続プログラムは、システムが生成した16文字の通信用パスワード、HKDF-SHA256、TLS 1.2 ECDHE-PSK、および ChaCha20-Poly1305 を使用します。任意の短いパスワードは受け付けず、証明書検証の回避や平文通信へのフォールバックも行いません。詳細と現時点の制約は[プロトコル文書](docs/protocol.md)を参照してください。

通信用パスワードは macOS Keychain に保存します。テキストのデータベースは、既定ではディスク上の永続ファイル `~/Library/Application Support/AudayWorkflow/default/library.sqlite` に保存し、Skill のインストール先とは分けています。モデル、設定、インデックスもローカルに保存します。まずテキストを同期し、音声は必要に応じて取得します。接続を無効にすると以後の読み取りを防げますが、別のデバイスにダウンロード済みのコピーを回収することはできません。

オンデマンド準備に対応した iPhone 版では、接続を有効にすると待ち受けが始まり、コンピューターが同期を要求した時点で資料のスナップショットを準備します。大きなテキスト記録は、再開可能な検証付きチャンクで取得し、保存済みの内容と出典との関連を保持します。現在の Skill は、事前にスナップショットを準備する旧版の iPhone 側実装にも対応します。

通信がローカルでも、クラウド型 AI アシスタントの推論までローカルで行われるとは限りません。タスクに必要な抜粋だけを返してください。完全にローカルなワークフローには、推論と後続のツールもローカルで動作する必要があります。

## 開発と検証

```sh
sh tools/git/install-hooks.sh
python3 tools/verify_public.py
python3 -m unittest discover -s tests -v
swift test --package-path scripts/link
swift test --package-path tests/native-peer
```

テストでは合成データを使い、暗号化接続、読み取り専用のアクセス範囲、スナップショットの整合性、ダウンロードの再開、オフライン検索を検証します。iPhone との接続確認には[実機テスト手順](docs/device-testing.md)を参照してください。Keychain を使うテストは明示的に有効化してください：`AUDAY_TEST_KEYCHAIN=1 python3 -m unittest discover -s tests -p test_pairing.py -v`。標準のテストに実際の録音やモデルのダウンロードは不要です。
